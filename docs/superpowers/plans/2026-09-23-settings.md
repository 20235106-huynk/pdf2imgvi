# pdf2imgvi Settings Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement these tasks in order. Each behavior change starts with a failing test.

**Goal:** Add an editable Settings view inside the workspace, persist ordinary settings in Chrome local storage, and keep the API key in either local or session storage.

**Architecture:** The workspace switches between Translator and Settings with React state. One settings model owns defaults and normalization; two storage modules own Chrome storage access. The Settings page keeps an unsaved draft and calls only those storage modules.

**Tech Stack:** React, TypeScript strict, Vite, existing shadcn Button, Chrome Manifest V3 storage, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-23-settings-design.md`

## Global Constraints

- Keep Settings inside the existing workspace; remove Settings from the popup.
- Do not add dependencies or PDF/translation/cache behavior.
- Never place the API key in `AppSettings`, IndexedDB, logs, or an error message.
- Preserve the user's unrelated `.gitignore` edit.
- Use defaults `en`, `vi`, `standard`, concurrency `10`, retries `3`, and `{original}_vi.pdf`.

## Review Focus

- A missing or corrupt stored settings value yields safe defaults.
- Out-of-range concurrency and negative retries are normalized before persistence.
- Migrating an API key between local and session storage leaves exactly one copy.
- An empty key removes both copies; key values never enter settings storage.
- The workspace still renders Translator after Settings navigation is added.
